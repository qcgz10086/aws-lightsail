# T06 持久任务、恢复与补偿

计划 V1.0（2026-11-17）。T06 BASE 固定为已独立审计交付的 T05 docs-only HEAD `4142d4544f3bd602d25fe74951b5c467736d253b`；对应产品 HEAD `33db3e4f6b04653b93d60e9e88f53d11d785ec94`。本任务仅在独立 worktree 实施，保留 Python/FastAPI/SQLAlchemy/SQLite、TypeScript/React 与当前两个容器部署结构。

## 目标与约束

- 建机、开关机/重启、换 IP、删除、手动和定时流量同步统一进入 SQLite 持久任务核心；兼容旧写接口，新增 `/api/v2/tasks` 提交、列表、查询、取消（仅未开始）和显式核对接口。
- 所有任务有 user owner、credential id、确认 account id/unknown-credential scope、region/resource 键、幂等键、受保护的请求指纹、状态、当前步骤、步骤事件、结果/错误和时间戳。任务请求中可能包含自定义实例密码；敏感 payload 整体 Fernet 加密，API/日志/事件中只输出白名单摘要，不存明文 key、secret key、代理密码或 password/userData。
- 状态机：`queued -> running -> succeeded|failed|partial`；检测到写意图已持久化而未确认结果、worker lease 失效或响应结果不明时进入 `reconciliation_required`。未知结果不自动重放。`reconciliation_required` 和待补偿任务保留资源锁，只有只读 AWS 状态证明结果、明确安全补偿完成或经用户显式决议后才解锁。
- SQLite v5 增加 `operation_tasks`、`operation_task_steps`、`operation_task_locks`。在现有 `schema_migrations` 单事务内升级；升级前包含 WAL 的一致性备份、SHA/完整性校验；DDL、数据校验、v5 ledger 原子提交。失败停止启动并保留原库/备份。T01-T05 格式及 v4 数据不改写。
- 单后端进程内固定 worker pool（最多2个资源变更任务并行）、现有 AWS limiter 总并发5。任务与步骤所有权更新用条件 token/version 防旧 worker 迟到写回。启动时 queued 可恢复；带未完成写意图的 running 标记待核对，不自动重放。任务终态保留30天后清理；未解决任务不删除。
- 幂等键在单用户范围唯一；相同键和相同请求返回原 task id，不同请求返回冲突。兼容入口在等待窗口内可返回原响应结构；超时返回 `202 + task_id + reconciliation/status URL`，前端跟踪任务直到终态，刷新页面仍可按 task id 查询。
- 锁基于 `user_id + (confirmed account_id | unknown credential_id) + region + resource`，避免同 AWS 账号不同 key 绕过互斥。traffic sync 持有账号范围锁，与该账号资源变更冲突；自动关机由 traffic task 通过同一锁/幂等核心提交，不能直接绕过。
- 凭证/账号/代理加密字段版本在任务执行及每个后续 AWS 步骤前重新核对；原 credential 删除或版本变更后不借默认 key/新账号继续。核对仅可使用明确选择且确认归属相同 AWS account 的凭证；身份未知不得升级为已确认归属。
- 代理约束：每个 AWS 子步骤必须使用创建任务时绑定的 credential 及该版本的 proxy；代理解密、DNS 重校验或网络失败不得回退直连。特别修复 `lightsail.create_instance` 默认 AZ 的 `get_regions(..., proxy_url=proxy_url)`。用实际 `aws_clients.make_client` factory 和 fake botocore client/transport 逐调用检查 AZ 查询、创建、状态查询、防火墙、静态 IP 分配/绑定/释放、换 IP、删除和流量/auto-stop，没有真实 AWS。

## 操作流程与失败语义

- 建机：提交前确认实例名不存在；确定性 task id 标签进入 `CreateInstances` 请求，绑定 AZ 目录查询与建机使用相同代理。逐步记录 `resolve_az`、preflight、create intent/result、等待状态、firewall、IP allocate/attach 和完成事件。已存在且带本 task marker 才能自动认领；同名但 marker 不同/缺失不得接管。创建响应丢失后只查状态和 tag；无法证明归属则待核对。防火墙/IP 部分失败显示 partial 与具体步骤，可独立补偿/重试，不重放已确认 create。
- 换 IP：持久化旧 IP 和确定性新 Static IP 名；allocate → 查询新 IP → attach → 查询确认新绑定 → detach/release 旧 IP。新绑定未确认绝不释放旧 IP。失败且能确认新 IP 未绑定时释放新 IP；若旧 IP 已 detach 则尝试恢复旧绑定；任何补偿结果不明保持锁和 reconciliation 状态，不整流程盲重放。
- 删除：先读目标实例和真实 `attachedTo == instance_name` 的静态 IP 清单，逐项记入任务；不使用 name 前缀猜归属。发起 delete 后必须通过只读查询确认实例不存在，才释放清单内静态 IP。删除仍 pending/响应丢失时先核对；清理失败保留逐 IP 重试步骤，不重跑 delete。
- start/stop/reboot：写意图后调用，响应丢失读取实例 state/operation；只有状态能证明目标结果时终结，否则待核对。自动关机走 stop task，不在 collector 中直调 AWS。
- traffic sync：账号范围 task 重采固定 UTC 月份/时间窗，对 TrafficUsage 使用原子 upsert/覆盖，重复安全；每账号/区域失败保留分步骤错误，部分成功为 partial，不把失败记成功。scheduler 只 enqueue 持久 task；同用户/账号/窗口幂等。sync 中的自动 stop 用同一个 account/resource lock 及幂等键。

## API 与前端

- `POST /api/v2/tasks` 校验 kind、请求体、credential owner 和幂等键，立即返回 `202 {task_id,status}`。`GET /api/v2/tasks` 只返回当前用户任务；`GET /api/v2/tasks/{task_id}` 每次查 owner；待核对任务提供受限的显式 reconcile/retry endpoint。跨用户 id/task key 恒为404，不泄露存在性。
- 旧 `/api/instances` 创建、资源 start/stop/reboot/change-ip/delete、`/api/traffic/sync` 均委托同一执行核心，不保留旁路同步 AWS 写调用。同步等待超时返回明确任务 id，不把超时说成失败。
- 前端写操作提交 task 后显示已接受状态并查询进度、步骤、部分完成、错误/待核对；账号/页面切换或刷新后不把旧 task 回调写入新账号数据。任务接受不等于 AWS 资源完成。

## 测试矩阵

- 数据库：新库与 v4 基线升级；验证 operation/task/step/lock schema、FK/unique/index、WAL backup hash/quick_check、v5 ledger；在备份、各 DDL、ledger 写和 commit 故障点注入异常，升级失败不启动且原库可打开；重复启动幂等。验证 SQLite 主数据库和 WAL 中已有业务数据都在备份恢复后。
- 用户/凭证：跨用户 task 查询/取消拒绝；同账号不同 credential 互斥；未知 account 按 credential 隔离；修改 proxy/key/account、删除 credential 在 queued、步骤间、重启后不允许旧 task 使用新/default key；encrypted payload 与错误日志无敏感串。
- 幂等/竞态：同 key 同 payload 并发只创建一个 task；同 key异 payload冲突；不同用户相同key隔离；task写失败后可重试且不重复 AWS 写；用户退出/reload 后 task 查询仍按当前 owner授权。
- 响应丢失/崩溃：fake AWS 在“已执行”后抛连接超时，覆盖 create、start/stop、allocate/attach/detach/release、delete 和 auto-stop；步骤 intent 已 commit 后杀 worker/进程，在重启后验证进入核对、锁未释放、无盲目重放；旧 worker lease/token 失效后的迟到成功/失败不得覆盖新 owner。
- 补偿边界：AttachStaticIp `Started` 但绑定未生效时旧 IP 不释放；attach 已生效但响应超时先只读核对新 IP 后再决定；新 IP 未确认/步骤失败时尝试恢复旧绑定；delete `Started` 尚存实例时不释放 IP；只清实际 `attachedTo` 与目标实例匹配的 static IP，不按 `-sip-`/`-ip` 前缀删无关或标记他用资源；cleanup 失败只重试 cleanup。
- 代理：实际 `aws_clients.make_client` + fake botocore client 构造多步骤探针，显式 AZ 与自动 AZ 均核对所有构造 client 的 Config.proxies；每个 fake transport 记录调用的 credentials/proxy/version；负向代理失败时真实 transport 调用计数始终0。包含默认 AZ `get_regions` 缺 proxy 的回归。
- 锁/容量：同 account 不同 key 的同资源变更、sync 与 auto-stop 冲突；跨账号/不同资源可调度但运行资源变更≤2、AWS calls≤5、同资源≤1；worker 重启释放安全 lease、未知 task 仍持锁。终态30天清理不删 unresolved。
- 流量：分页、区域慢失败、多账号部分成功、重复执行不累加、自动关机阈值冲突共用 lock、调度与手动同步合并。前端验证提交202、各状态查询/重试/恢复、切用户与旧响应隔离。

实施顺序：先提交本计划；随后补 v5 migration/fault tests 和 proxy/单步 stateful fake；实现 task models/repository/state transition/locks；实现 worker 与可核对的 operation steps；改写 v2/legacy/scheduler 入口；配套前端 task tracking；运行迁移、后端全量、TSC/Vite 与浏览器回归；生成固定产品/交付 identity、日志和证据 SHA 后交独立审计。不得调用真实 AWS、部署、推送、合并或关机；T06 独立通过后再进入 T07/最终集成。
