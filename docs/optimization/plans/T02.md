# T02 账号与代理实施计划

依据 V1.0（2026-11-17）。本任务 BASE 为 T01 独立通过的 `541967282fa85aff8861a33ae3c6f2b483ccf273`；实施限于本文件列出的账号身份、客户端/代理及重复 Key 策略行为。

1. 在版本化 SQLite 迁移中增加可空 `aws_credentials.account_id` 和自动关机冲突暂停标志。继承 T01 的 `BEGIN IMMEDIATE`、完整性门禁、前置快照、原子台账和失败停机；未知历史凭证身份留空，升级不主动调用真实 AWS，不根据 Key 文本推测 AWS 账号。
2. 凭证新建、密钥更换、手动验证和兼容写入口使用当前生效的凭证与代理调用 STS `GetCallerIdentity`。只有合法的 12 位 Account 写入账户身份；权限/网络/代理失败保持身份未知并明确报告，不能回退直连或沿用旧 Key 的身份。密钥或代理改变使旧身份失效，成功验证后按 AWS 账号更新。
3. 建立共同 boto3 会话/客户端构造入口，显式采用当前 Access Key/Secret 和已校验代理，覆盖 Lightsail、Service Quotas、Account、STS、Billing、Cost Explorer；代理解密、解析、可用性或 SOCKS 支持失败时停止。只有用户明确清除代理才允许直连。把更新、兼容更新时损坏的代理密文与“未传代理字段”区分。
4. 对同一面板用户与已确认 AWS 账号，把区域和实例视图按账号合并；数据库中的流量、操作与设置仍按明确 `credential_id` 保留。多个凭证发现同名实例时不把用量重复累加。未知身份各自隔离且不计入账号确认归并。
5. 识别同一用户/账号/区域/实例跨凭证的自动关机配置冲突：保留每条原设置，不选优先 Key、不搬数据；所有冲突策略暂停并响应中标明冲突。协调自动采集、用户触发同步及直接修改策略，避免通过切换默认凭证恢复其中一条策略。其他实例及其他面板用户继续各自处理。
6. 先为账户绑定、身份失败、密钥与代理改变、显式清理/损坏密文、客户端代理透传、跨用户隔离、同/异账号重复 Key、单/多策略冲突及跨入口同步补临时 SQLite 和 mock AWS 回归；不调用真实 AWS。运行 T02 专项、后端全量，测量迁移前置备份和小型账户操作，并记录限制。
7. 固定产品实施 HEAD 后自查差异、生成证据及交接单。交独立审计绑定固定 BASE/HEAD；有阻断先核实返修并重新交审，独立审计放行后方可进入 T03。

## 行为边界

- 确认的账号身份键是 `(user_id, account_id)`。不同面板用户不互相归并；凭证 ID 始终用于选取具体 Key/代理和 AWS 写操作。
- 账号未知时绝不通过匹配 Access Key ID、标签或端点猜身份。未知身份不计入确认账号总量，也不能据此自动将不同凭证策略合并/互相覆盖。
- 换 Key 后清空旧 `account_id`，先用新 Key 和当前代理重新做 STS 校验；不能将原账号 ID 沿用到新密钥。新账号只创建新的身份范围；旧流量、赠金和策略不搬家。
- 同账号同实例的显式“开＋关”以及“开＋开但有效阈值不同”都构成冲突；“关＋关”和相同阈值的启用不冲突。无策略记录与显式关闭不同。保留每条设置并暂停冲突策略，不能通过切换默认 Key 绕过。
- 已检测的冲突暂停持续保留；普通 PATCH、改默认 Key、单条保存成相同值均不自动解除。`GET /api/instances/{region}/{name}/policy-conflict` 返回当前用户该实例全部竞争策略及确认指纹；只有全部身份已确认、开关及有效阈值一致，并在 PATCH 中提交完整 `resolve_conflict_credential_ids` 与匹配的 `resolve_conflict_token` 才解除。遗漏、跨用户、过期确认或身份未知均返回 409。前端先展示全部策略供明确确认，表单使用原始配置值且只保存触及字段。
- STS 临时失败时，当前身份变为未知，最后确认账号仅用于保守的冲突停止判断，不用于确认总额、资源去重或数据迁移。已绑定账号的策略在身份未知或变化时暂停；从未确认身份的凭证继续只使用自己的显式策略。历史策略包括明确关闭在迁移后完整保留。
- 流量记录以采集时账号快照与明确 `credential_id` 保存。换账号不修改旧记录，同月同名的新账号可单独写入；旧未知记录保留待核对且不计入地区确认总额。策略冲突按用户一次批量计算，实例列表与流量摘要避免逐实例全用户重算。
- 上游 API 本身不提供代理失败回退机制；应用解密/校验每次调用所用的存储代理，并对失效代理中止请求。未配置代理的直连是明确配置状态。
- 明确直连通过 botocore 的显式代理空值实现，忽略进程 HTTP_PROXY/HTTPS_PROXY；配置代理时 NO_PROXY 不改变该凭证代理路径。
