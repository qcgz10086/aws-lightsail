## 二、目标与技术约束

优化多账号数据准确性、页面加载速度、资源占用和操作失败恢复。

- 保留 Python 3.12、FastAPI、boto3、SQLAlchemy，以及 TypeScript、React、Ant Design。
- 保留两个容器、Nginx、SQLite、单后端进程；缓存和任务状态存入 SQLite。
- 不引入 Redis、Celery、独立消息队列或其他语言重写。
- 保留凭证加密、登录保护、用户隔离和代理校验机制。
- 只修改当前任务需要的内容，不夹带无关重构。
- 在独立 Worktree 开发，保留已有修改。未经明确指令，不合并、发布、部署或调用真实 AWS 账号。

## 四、必须落实的行为与接口

- 账号身份：以面板用户 ID＋AWS account_id 归并，同账号多 Key 只汇总一次；具体操作保留明确 credential_id。身份未知不计入确认总额，换账号不自动迁移旧配置。
- 配置冲突：重复 Key 对同实例的自动关机配置冲突时，保留原记录、标记冲突并暂停策略，不能通过切换 Key 绕过。
- 账单：使用 Decimal；新接口金额使用十进制字符串。Credit 按记录类型统计，不用 UnblendedCost 与 NetUnblendedCost 的差额冒充赠金消耗；退款、折扣分别处理。
- 赠金：官方余额与估算余额分别展示；手动记录无可靠匹配时不计算每笔剩余。匹配官方 Credit ID 后不重复计入余额，无所属历史记录进入待归属列表。
- 查询范围：费用限定到对应账号，避免组织总额与成员账号重复相加；GetCredits 使用账号自身范围。币种分别汇总，费用、预测、赠金各自报告状态。
- 缓存：默认账单 30 分钟、实例 60 秒、目录 24 小时；先展示快照再刷新。按用户、账号、范围及凭证/代理版本隔离；权限失效或凭证变更作废相关缓存。
- 失败展示：有旧值时保留最近成功时间，标记过期及错误；冷缓存失败结束等待。慢账号和失败区域不能遮住其他成功数据。
- 容量并发：AWS 总并发默认 5，资源变更同时最多 2，同实例最多 1；缓存有效载荷上限 64 MiB，终态任务历史保留 30 天，未解决任务继续保留。
- 任务恢复：操作前记录意图及资源标识，操作后记录结果；超时或重启先核对 AWS 状态。未知结果进入核对状态，不盲目重放；未解决任务阻止冲突操作。
- 补偿：新 IP 绑定确认后再释放旧 IP；失败尝试恢复旧绑定。删除确认后再清理静态 IP，清理失败可重试。自动关机、定时同步和手动操作共用互斥规则。
- 迁移恢复：备份包含 WAL 数据并通过完整性检查；迁移失败停止启动。回退同时恢复数据库和配对镜像，并重新核对未终结任务。
- 接口：新增 `/api/v2/billing/summary`、`/api/v2/instances`、`/api/v2/refresh`、`/api/v2/tasks` 及任务查询接口。提交任务返回 202＋task_id；查询检查用户归属。
- 兼容：旧查询接口保留结构；旧写接口接入共用执行核心。同步等待超时返回明确任务标识和待核实状态，前后端配对升级。

## 五、验证、审计与交付

必须测试账号隔离、重复 Key、Credit 冲正、退款、多币种、分页、代理异常、缓存失效、请求竞态、重复提交、AWS 已执行但响应丢失、步骤中崩溃、自动关机冲突及数据库恢复。

相同环境和固定模拟 AWS 数据的性能对比目标：热缓存首屏 P95≤1 秒；冷缓存首批数据中位耗时降低至少 30%（基线已低于 1 秒时不退化）；完整刷新不慢于基线；有效期内不新增同范围 AWS 查询。镜像总体积不增加，后端空闲内存增量≤32 MiB，刷新峰值增量≤64 MiB。未达标必须报告，不自行降低标准。

每次交付包含任务编号、计划版本、工作目录、BASE、HEAD、变更说明、测试命令与结果、性能证据、未验证项和已知限制；交接单保存到 `docs/optimization/handoffs/Txx.md`。

收到审计意见后逐项核实，修复并提供新 HEAD、对应证据及影响范围。审计结论绑定具体提交；修改后重新交审。实施者不能代替审计者宣布通过，不能把未执行测试写成已通过。
