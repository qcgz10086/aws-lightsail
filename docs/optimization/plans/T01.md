只实施 T01；B01 留至 T03，N01 留至缓存/v2 测量适配，N04/N05 留作测量工具维护。沿用 Python 3.12、SQLAlchemy、SQLite、两容器和单后端进程。无需真实 AWS。

1. 使用临时 SQLite 库补充失败测试，覆盖旧单凭证表重建时字段、外键和行数保留，旧策略/流量归属，无法归属时停止迁移，新库与当前多凭证库版本台账及重复启动。
2. 将迁移放入显式 BEGIN IMMEDIATE 事务，重建时使用模型 DDL 和明确列映射；关闭外键仅限迁移连接且在事务前设置，提交前校验全部外键，避免 RENAME 父表导致子表引用旧名称或触发级联删除。版本台账与业务 DDL 一起提交。未知高版本停止启动。
3. 非空磁盘库升级前，在持有写锁但未修改数据库时，从独立只读 SQLite 连接使用 backup API 创建一致性快照；包含 WAL 已提交数据。校验 integrity_check、foreign_key_check，保存路径/哈希并使用受限文件权限。备份失败不执行迁移。
4. 添加可独立运行的离线 backup/verify/restore CLI，不依赖应用密钥配置。恢复先验证源备份及 SHA256，保留当前库安全快照，再原子替换完整暂存库；要求后端及所有数据库访问进程已停止。保留配对镜像和任务核对的操作文档，禁止自动部署或调用 AWS。
5. 执行新库、旧单凭证库、当前多凭证库、事务中故障、WAL 数据恢复、损坏/哈希错误备份拒绝等测试；回归现有后端测试，记录命令、退出码及未测项，作者自查后提交 docs/optimization/handoffs/T01.md，交独立审计。

复核重点：凭证密文逐字保留；默认凭证仅为无该列的历史记录补值；旧策略无法归属时不得丢行；主表重建不得破坏子表外键；SQLite DDL 故障回滚；迁移台账不与事务分离；WAL 中已提交行进入备份；恢复拒绝错误源且不污染当前库。未来任务表不存在，恢复文档要求 T06 后核对未终态任务，当前不声称通过任务恢复测试。
