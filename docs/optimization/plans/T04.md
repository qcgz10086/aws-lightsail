计划 V1.0（2026-11-17）；BASE 为已独立通过 T03 的 `1dd5d56c3bc637aeec9439c64f316f7f8f391438`。独立工作树 `C:\Users\liyang\.codex\worktrees\t04-backend-cache\aws-lightsail`，分支 `codex/t04-backend-cache`。

1. 先补临时 SQLite 与固定 mock 回归：热缓存不访问 AWS、同范围刷新合并、跨用户/账号/凭证代理版本隔离、过期旧值/冷失败终止、权限失效清除、失效期间旧请求不能回写、64 MiB 有效载荷上限、重启租约恢复、总调用并发限制。
2. 数据库 v4 增加快照表，持久化有效载荷、成功时间、TTL、错误和短刷新租约。TTL 账单1800秒、实例60秒、目录86400秒；短暂失败保留旧值并退避，冷失败明确结束等待。失败不覆盖最近成功时间；权限/身份失效不可继续返回旧权限数据。
3. 缓存键包含当前用户、确认账号或未知credential、查询范围（账单按UTC日期，防跨日预测口径重叠）、凭证/代理加密版本指纹和用户token版本。后台刷新仅使用不可变原语及独立数据库连接；发布前再次核对版本，过时结果丢弃。SQLite条件租约合并并发；刷新由本进程单独事件循环执行，最多128个待执行范围、AWS调用另受5并发限制；重启后租约超时可接管，不重放资源写操作。
4. `/api/v2/billing/summary` 加快照元数据，`/api/v2/instances` 按账号/区域返回可用快照和独立状态；冷启动先返回等待状态，轮询可先拿已成功范围。`/api/v2/refresh` 只请求同一缓存刷新核心；兼容查询保留结构。目录查询复用24小时缓存。前端共享缓存/取消/懒加载留T05。
5. 所有 boto3 API 调用共用进程级默认5并发，资源变更最多2，同实例最多1；不持有数据库事务等待网络。客户端显式超时/重试上限，代理失效不直连。T06再持久化业务任务、冲突操作恢复与补偿。
6. 保留并复用T02批量策略/设置/流量查询，避免新N+1。测试、自查、固定BASE/HEAD与性能/未验证项写交接单，自动交“优化审计”；未独立通过不进T05。双方禁子代理；不合并推送发布部署、不关机、不调用真实AWS。

区域接口先限制长度/字符，再用本地botocore Lightsail endpoint目录拒绝任意区域，最后核对该凭证已缓存的区域目录；不支持区域不得创建实例scope或访问AWS。GET默认立即快照，`wait=true`为兼容/明确等待模式；前端有限跟进30秒、显示最近成功/过期/错误，手动刷新接共用核心。业务持久task_id由T06任务模型统一补齐，不把缓存租约冒充资源操作任务。
