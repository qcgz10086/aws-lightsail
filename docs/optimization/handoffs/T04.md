## 修改内容

- SQLite v4 增加 `DataSnapshot`：范围键、用户/账号/凭证版本、JSON 有效载荷及字节数、成功/过期时间、错误/重试时间、条件刷新租约。账单 TTL 1800 秒、实例 60 秒、目录 86400 秒；保留单 SQLite/单后端进程。迁移使用既有一致性备份、事务台账、失败停机和恢复门禁。
- 范围键包含用户 ID/token_version、确认 account_id、credential_id、凭证/代理加密版本指纹及查询范围。数据发布在 `BEGIN IMMEDIATE` 内复核当前版本和租约；更换凭证/代理、令牌撤销和操作失效之后，旧请求不能回写。凭证更新/验证和成功资源操作清除对应有效期及租约。
- 条件租约合并同范围刷新；后台读取使用独立事件循环、不可变输入和独立 Session。最多 128 个待执行范围、单 loader 等待上限 25 秒、租约 300 秒、失败退避 15 秒。重启后可接管过期读取租约，不重放资源变更。shutdown 等待刷新/线程池结束，后续 lifespan 可重建。
- 过期快照可先返回；短暂失败保留最近成功值/时间并标记过期、错误；冷失败明确结束刷新。权限失败清除同凭证同类快照，身份变化清除该凭证全部范围；临时 STS 故障保留旧身份快照并暂停刷新。账单费用/预测/赠金、实例各账号区域保留独立状态，慢或失败范围不覆盖已成功值。
- 缓存 JSON 有效载荷总和上限 64 MiB，超限先淘汰最旧有效载荷；单个超限发布被拒绝，保留原成功值。该限制针对有效载荷，不能将其解释为 SQLite 文件或进程内存大小上限。
- boto3 客户端统一显式超时/重试和进程调用约束：总并发 5、资源变更最多 2、同区域同资源串行（跨账号保守串行）。沿用 T02 代理失败不直连。读取快照/发布使用批量版本、范围和租约查询；沿用批量策略/设置/流量查询，并移除预加载流量路径每实例无用的查询对象构造。
- 新增 `/api/v2/instances` 和 `/api/v2/refresh`，账单 v2 接快照核心；GET 默认立即返回，`wait=true` 明确等待。旧查询保持原结构并复用缓存等待核心，目录复用 24 小时快照。region 先限制长度/字符，再校验本地 botocore Lightsail endpoint 目录及凭证区域目录；非法值在 AWS/实例 scope 创建前被拒绝。
- Billing/Instances 页面接入快照状态，保留可见旧值、成功时间、过期和失败提示；手动刷新走共用核心，有界跟进 30 秒并防止旧版本响应覆盖。通用共享请求缓存、取消和页面懒加载仍属 T05。
