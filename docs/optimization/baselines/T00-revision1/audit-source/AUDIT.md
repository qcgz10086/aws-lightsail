## 已确认问题

### F01 / P2：容器补测缺少可执行路径

- 位置：`tools/optimization/run_baseline.py:54`、`:59`；`tools/optimization/README.md:21`、`:75`；`docs/optimization/plans/T00.md:34`。
- 触发：按照 README 在有 Docker 的机器复现，期望补齐镜像总体积、后端容器 CPU、空闲与峰值内存。
- 实际：驱动无论 Docker 是否可用，都把这些指标初始化为 null；有 Docker 时仅执行版本查询，并提示需要另外运行容器 fixture。交接代码和 README 没有该另外运行的可执行命令或驱动。计划第 6 步要求 Docker 不可用时保留未测项和复现命令，当前只有原生测量命令。
- 影响：更换机器不能直接补齐资源证据，后续无法依据此包验证镜像体积及内存增量目标。披露 null 是正确处理，但不能替代补测方法。
- 证据：已审读完整驱动和 README；原始 `environment.json`、`summary.json`、`verification.json` 均记资源未测，独立主机也未发现 Docker。
- 要求：补交可以执行的独立容器基线流程，明确固定源码、两种镜像的标识/构建输入、工作负载、CPU 窗口、空闲及峰值内存定义、采样与原始结果输出。补测仍须使用虚构凭证和隔离数据库。不得将本次原生 RSS 填入容器指标。

### B01 / P1：既存的跨 AWS 账号手动赠金估算归属错误

- 状态：已确认存在于 BASE，**不属于 T00 新增回归，不要求在 T00 修改业务代码**；须进入账单修复任务的验收清单。
- 位置：`backend/app/routers/billing.py:65`、`:111`、`:121`。
- 触发：同一面板用户绑定两个不同 AWS 账号，并分别创建手动赠金记录；查询其中一组凭证的账单。
- 实际：路由读取该用户全部手动记录，却用当前选中的同一个 CE client 计算每条记录的累计抵扣，没有按记录的 credential_id 选择账号。
- 影响：两个账号的抵扣不同，另一个账号的记录会被赋予当前账号的估算。该问题涉及账单展示准确性，未构成已确认的跨面板用户泄露。
- 证据：`audit-evidence/account-probe.json` 中 credential_id=3 属于 BETA；默认账单账号是 `111111111111`，返回的 BETA 手动记录却标有 applied=8、remaining=92，三个 CE 查询事件全部使用 ALPHA。固定 fixture 恰好为两个账号返回相同费用，故不能据此量化真实金额误差，但错用账号的查询路径已确认。
- 后续：使用不同账号的不同抵扣数额验证修复，同时验证默认凭证、显式选择凭证、重复 Key 和其他用户记录的隔离。

## 非阻断建议

### N01 / P2：测量就绪条件需在后续接口适配前收紧

- 位置：`tools/optimization/readiness.mjs:8`、`:12`；`browser_benchmark.mjs:25`、`:78`、`:83`、`:87`。
- 触发：页面保留旧值/正数占位，或收到响应后延迟提交新的业务状态。
- 观察：统计项只检查包含非零数字和有布局矩形，不能证明是当前一轮数据或在首屏可见；完整阶段等已观察请求结束及两帧，不能证明延迟的 UI 更新结束。刷新首批检测还被完整 primary response 的等待所限制。
- 定向证据：`timing-probe.mjs` 让值 1 立即显示，API 约 1 秒结束，值 2 至少在 1.7 秒后提交。原驱动退出 0，首访 complete 约 1074.8 ms、刷新 complete 约 1123.8 ms，均早于新值提交；同一初始值的重访首批约 53.5 ms、刷新首批约 1090.4 ms。
- 影响：复用此驱动衡量旧值缓存、分批加载或延迟渲染时，可能误报首批/完成时间。
- 限定：这是已复现的测量边界限制，不等于已证明 T00 原始真实页面的 180 个样本误报。T00 交接已说明 v2 与 SPA 场景需要后续适配，故本项不单独阻断当前 T00。
- 建议：适配时明确本轮数据/版本标记、首屏可见条件和完整业务就绪条件；区分网络完成与渲染完成。保留原基线定义和可复算的请求时刻，不能只改计时使结果更小。

### N02 / P3：网络限制不能作为整个进程全面断网证明

- 位置：`tools/optimization/fake_aws.py:17`、`:33`；`benchmark_server.py:199`；`offline_proxy.mjs:15`、`:33`。
- 已验证：未知 AWS 凭证/操作拒绝、真实 botocore 操作拒绝、外部 TCP connect 拦截、HTTP/CONNECT 精确来源转发。正式原始结果及独立 API/两样本运行均未报告未匹配 AWS 调用。

- 建议：需更强边界时采用网络命名空间/防火墙或完整的进程隔离，并记录拒绝事件。不得把当前测试夸大为全部网络协议的出站阻断验收。
